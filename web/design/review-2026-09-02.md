# App review, 2026-09-02

One evaluation pass over the whole app: `impeccable critique` plus `impeccable audit`, three
isolated assessments, judged on the dev server at 1440 / 1024 / 768 / 375 in both themes, driving
the real flows. This is the ranked list Mark picks a batch from. It is a work list, not a spec;
delete it once it is spent.

**Scores.** Nielsen heuristics 27/40 (acceptable, significant work needed). Audit dimensions:
accessibility 2/4, responsive 2/4, performance 2/4, theming 3/4, anti-patterns 4/4.

**The AI-slop verdict is a clean pass.** Zero shadows in the codebase, no glass, no gradient text,
no hero-metric template, no side-stripe borders, no modal, no em dashes in copy, and zero
hardcoded colors anywhere (every color is a `light-dark()` token). The one scanner advisory
(0.65rem on the info glyph) is icon optics, not a type-ramp break; document the size in
`DESIGN.md` rather than change the code.

**Fixed already** (2026-09-02, before this list was written): the score band's top row rendered
`left: 100%, width: 0%` whenever a score's low end equalled the scale max, which is every
Artificial Analysis point score. The best model showed no bar. The geometry now lives in
`bandSpan` in `web/core/score-view.ts` with three tests, and the view reads it.

## 1. The table is not showing the answer

The strongest theme, and all three assessments reached it independently.

- **The Model column is 121px at every width.** `COLUMN_WIDTHS` in
  `web/components/catalog-table.tsx:20` pins nine numeric columns at 999px and gives Model the
  leftover against `TABLE_MIN_WIDTH = 1120`, so it never grows into the 1,066px available at
  1440. Measured: 13 of 23 rendered names truncate ("Gemini 3.1 Pro Preview" needs 171px). The
  full name lives only in a `title`, which is mouse-only. Search compounds it: five consecutive
  rows read "Agentic Chat …" with no highlight, so a match looks arbitrary.
- **The table clips its right edge at 1440** (scrollWidth 1120, clientWidth 1066), and the
  `.quiet-scrollbar` treatment hides the scrollbar until a scroll fires, so there is no
  affordance at all. At 1024 five columns are gone, at 768 six, at 375 seven.
- **Scrolling right at 375 loses the model's identity**: no column is horizontally sticky, so at
  full right the screen shows four numeric columns and nothing naming the row.
- **The results region is not keyboard reachable** outside Chrome: the scroll container has no
  `tabindex`, no `role`, no name (`catalog-table.tsx:138`). WCAG 2.1.1.
- **The virtualized table misreports its size**: 23 `<tr>` for 2,032 models with no
  `aria-rowcount`, `aria-rowindex`, caption, or accessible name. WCAG 1.3.1 / 4.1.2.
- **Zero survivors renders a bare column header.** `CatalogTable` has no empty branch; the good
  recovery card sits about 1,400px away at the bottom of the rail.
- **There is no row count above the table**, so the results surface never says how many rows it
  holds.

**The dark theme also loses the architecture the light theme is built on.** Rail against bench is
12.81:1 in Blueprint and **1.06:1** in Night. Row borders 1.26:1, the score band's track 1.03:1,
the hatch 1.18:1. In Night the table has no visible grid, the band has no visible scale, and the
signature unknown-state treatment is the least visible thing on screen. `DESIGN.md`'s Dark Rail
Rule is not met; the rule is right and the token drifted.

Separately, the band's track uses `bench-2` while sitting on `card`, which is a wrong-token case:
`bench-2` is defined as a shade of the bench. Give the band its own token.

## 3. The score never says what it is

- **The Score column header says "SCORE" for both a four-digit Elo and a two-digit 0-100 index.**
  The source and its measurement date live in a hover attached to a different control, so the
  user carries the units in their head. Design principle 2 says every number shows its receipts.
- **Flipping the source silently deletes the score floor.** `clearFloor` in
  `decision-surface.tsx` is correct behaviour (the metric vocabulary changes) and it is
  unannounced. The app's own promise is that every gate names itself when it fires.
- **During the browser fetch the toggle claims Artificial Analysis while the board still holds
  LMArena numbers**, and `aria-pressed` follows the claim, so a screen reader hears the new
  source selected before the numbers change.

## 4. Layout and scrolling

- **The rail and the bench scroll as one page.** The aside is `lg:sticky lg:top-6` inside a grid
  row whose height is the aside's own, so sticky has nothing to act in. With two rows open at
  1440x900 the aside is 1,358px. Reaching Score floor takes the count, the header, the toolbar
  and the whole table off-screen, and leaves about 500px of empty page beside the rail. The
  product's core moment (watching the count drop as a gate fires) is unavailable in exactly the
  situation that produces it.
- **At 200% text size the search box collapses to 50px wide.** `md:max-w-[26rem]` on the source
  switch is a rem cap that claims up to 832px while the search wrapper has no floor. WCAG 1.4.4.
- **At exactly 1024 the search box is squeezed to 186px** and truncates its own placeholder. It
  fits at every other width tested.
- **Info tooltips clip off-screen at 375**: fixed `w-72` with a hard left or right anchor and no
  collision handling, measured at x = -75 and right = 400 on a 375 viewport. The hidden text is
  unreachable. WCAG 1.4.10 / 1.4.13.
- **The info trigger eats 27px of the source segment it sits inside.** Its `::before` pad wins
  `elementFromPoint` over the segment button, so 27 of the LMArena cell's 92px do not select
  LMArena. WCAG 2.5.8.
- **Typing in search pushes the blend row and the table down 134px** when the cut-matches panel
  appears. `DESIGN.md`'s Reserved Slot Rule covers this class of bug and currently names only
  numbers; widen it to panels.

## 5. Performance

- **A cold build can ship with no scores at all.** `servingLastGood` holds its memory in module
  scope, and `next build` and every ISR regeneration worker are cold by definition. A local build
  taken during this review baked in `"arena":{"status":"unavailable","reason":"HTTP 429"}`: no
  score column, no band, no blend editor, no Score floor rule, for the whole revalidate hour. The
  currently live deployment is fine (`status: ok`, measured 2026-09-01), so this is a risk, not
  an outage. Fix: commit a dated snapshot as the floor `lastGood` so a cold failure degrades to
  the `stale` path the UI already speaks, and fail the build rather than prerender a scoreless
  page.
- **5.17 MB of HTML per cold load** (335 KB gzip), of which the RSC payload is 4.59 MB and the
  rendered markup is 12.6 KB. A field census found **36% of the payload is never read by any
  code**: `description` (728 KB), `openRouterId` (356 KB), `sdk` (239 KB), `lastUpdated` (194
  KB), `attachment` (131 KB). Project the identities to a display-and-rules shape in `page.tsx`.
- **The prerendered table is empty** (`<tbody></tbody>`): the virtualizer has no scroll element
  on the server. First paint shows column headers, then a 263ms long task blocks the main thread
  before 31 rows appear. Pass `initialRect` so the server renders a first window.
- **The `board` memo never holds until the user clicks a stepper.** `weights` at
  `decision-surface.tsx:70` allocates a fresh record every render while `weightsBySource[source]`
  is undefined, which is the load state, so every keystroke re-scores and re-sorts every
  survivor. Measured at about 15ms per keystroke, and it vanishes entirely once a stepper is
  clicked. One-line fix: memoize `weights`.
- **React Compiler is not installed, and the code assumes it is.** `catalog-table.tsx:122`
  carries a comment about what the compiler cannot memoize plus an eslint-disable, while nothing
  in `web/` is memoized at the component level. Decide it: turn the compiler on, or memoize
  `CatalogTable`, `RuleRail`, and `BlendEditor` by hand (which then makes `options` and `cuts` in
  `decision-surface.tsx` load-bearing).
- **The virtualizer's row estimate describes the wrong rows.** `ESTIMATED_ROW_HEIGHT = 38` is the
  unrated rows at the bottom; rated rows measure 53, 85, or 101. Total content grows 2,826px as
  rows measure, all of it in the section the user opens on. And with no `getItemKey`, measurements
  cache by index, so every re-sort keeps stale heights.

## 7. Minor, and documentation drift

- An open rule row states its state three times: the summary sentence, the cut line, and the chip
  suffix. Two would do.
- The cut-matches panel repeats one rule name on five consecutive lines; group them.
- The active source segment uses `font-medium`, which changes the segment's width, so the control
  moves under the pointer that clicked it.
- Table rows have no hover state and no zebra, at 1,120px wide with 1.26:1 borders.
- The metric `<select>` and the month input are the only OS-drawn controls on the page, both on
  the dark rail among hand-built chips.
- Reseller `$0.00` prices pass as measured values and survive a `$0.0001` fence.
- Opening Sellers puts 212 checkboxes in the tab order before the next rule (Makers is 44).
  Escape works and is undiscoverable. No skip link anywhere.
- Search results are never announced; the count, the emptied-by card, and the source note all
  have live regions and this does not.
- The first heading in DOM order is an h2 ("Your rules") before the h1. The aside is an unnamed
  complementary landmark. `aria-expanded` on the tooltip trigger is the wrong pattern; it already
  has `aria-describedby`.
- `accent-deep` is defined, exported, and used nowhere, while `DESIGN.md` calls it "the deep hover
  step".
- Numeric table cells carry `tnum` but not `font-mono`, against the Measured Mono Rule. Pick one:
  add the font, or narrow the rule.
- `max-h-[max(20rem,calc(100dvh-11.25rem))]` encodes the summed height of the header, toolbar and
  blend row with nothing enforcing it.
